# 2026-11-06 压测计划

## 环境与口径

- 应用：2C4G ECS + RDS MySQL，新 jar（异步 + 分桶），`SHOP_SECKILL_ASYNC_ENABLED=true`
- 压测：独立 2C4G ECS，JMeter 5.6.3，走内网访问应用（`172.30.0.100`）
- JFR/GC 日志关闭；正式测量前预热 9×120s（约 18 分钟）商品列表
- 混合场景 burst 窗口 = 测试开始后前 15 秒
- 活动与库存：001=10、002/003/004/005=500、007=10、008/009=50

## 场景

| 编号 | 场景 | 参数 | 目的 |
|---|---|---|---|
| S0 | 商品列表 | 50 线程 / ramp 10s / 180s | 确认无回归 |

## 采样

S4a/S4b/S4c 与应用机并行执行：

- `sample-mysql.sh`：Threads_running、行锁等待、Questions
- `sample-app.sh`：Tomcat busy、Hikari active/pending、堆内存
- `sample-nginx.sh`：stub_status

## 验收标准

- 功能：各活动订单数 = 库存；无重复用户；无超卖；主队列与 DLQ 为 0
- S2/S4c：HTTP 500 应为 0
- S4a/b：突发期冷请求 p99 相比 S3 劣化 ≤50%
- 资源：Hikari pending 接近 0，行锁等待接近 0
- 记录异步模式的口径：POST 返回 PENDING 即计入样本，订单由消费者落库，需在跑完后核对订单数
