## 一、这一轮的目标

把 DoroShop 从「通用商城 + 秒杀」演进为「盒马式生鲜闪购」。三条原则：

1. **换皮不换引擎**：现有的库存预扣 / 分桶 / 幂等 / 异步下单 / 对账全部保留，新增的只是生鲜的领域规则；
2. **保持单体**：不引入 Nacos / Gateway / Sentinel / Seata 全套，最多拆一个服务；
3. **每个阶段必须有 before / after 数字**，没有数字的改造不算完成。

## 三、已定决策（不要推翻）

1. **不换项目主体**：题材是电商没关系，稀缺的是「基线 → 定位 → 改造 → 复测」这条链，重建等于清零。
2. **不做微服务**：「因为要手机看所以用微服务」是错的，手机看是客户端问题。要做只做一个最小拆分。
3. **不做「热点预测」**（不上 Prophet/ARIMA），做「热点识别 → 预热 → 失效一致性 → 命中率验证」闭环。
4. **ES 必须带评估**：没有 NDCG 前后对比，「我用了 ES」就是空话。
5. **数据先重构**：ES、热点、分店库存三件事全都卡在数据不真实上。

### P0 数据重构要点

现在 `Shop/sql/gen_product_spu.sql` 是 8 万条「压测商品-N」：同一张图、价格线性、销量线性、只有 4 个二级类目，没有任何一个维度真实。

- 商品名词表组合（品牌 × 品类 × 规格 × 产地），让分词 / 同义词 / 相关性有意义；
- 销量服从 Zipf（头部 1% 占 60%），热点才会自然涌现；
- 时间按午晚高峰 + 周末分布，给热点识别提供燃料；
- 状态分布：5% 下架、3% 无库存、2% 逻辑删除、10% 无图；
- 用 `LOAD DATA LOCAL INFILE`，灌数前 `SET unique_checks=0, foreign_key_checks=0, autocommit=0`，**先灌数据后建索引**。

## 五、盒马与普通电商的差异（P1 的立足点）

| 维度 | 现在 | 盒马式 |
|---|---|---|
| 库存粒度 | SKU 级 | **门店/前置仓 × SKU**（1 万 SKU × 50 仓 = 50 万行） |
| 超卖单位 | 商品 | 门店-商品-时段 |
| 地理约束 | 无 | 3 km 内、按仓拆单 |
| 履约 | 待发货/已发货 | 拣货→打包→出库→配送→签收，多状态 + 波次 |
| 损耗 | 无 | 临期、缺货、称重，库存会自然减少 |
| 时间 | 无 | 截单时间、预约时段 |

**关键**：现有 8 桶方案要升级成「分仓 + 分桶」。分桶和分仓是同一类问题（把热点拆开），这一步是唯一值得写进简历的领域差异。

## 六、约束

- 单机 2C4G，backend `-Xmx1g`、`mem_limit 1600m`；加 ES 要考虑内存。
- 单实例假设：`@Scheduled` + JVM 本地锁，多实例会重复执行。
- 无 CI、无监控；加 GitHub Actions（`mvn test` + `npm run build` + `oxlint`）成本低。
- 仓库 public：不提交 IP / 密码 / 真实 `.env`；`resume/` 已在 .gitignore。
